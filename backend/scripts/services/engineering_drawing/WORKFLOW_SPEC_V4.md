# 工程图双语翻译生产规范 V4.0

状态：唯一有效生产规范。旧 V2/V3.x 的相反语义全部失效；实现、主管提示、测试和发布门禁必须以本文件及 `workflow_policy.py` 的 `v4.0-readable-zone-complete` 快照为准。

所有环节必须通过 `orchestration_harness.py` 交接，携带同一个源文件哈希、V4 版本、策略指纹、稳定源行号、分区和逐块 A/B 渲染模式。下游只能补充证据，不得重新解释、降级、合并丢失或更改上游决定。流程固定为主管规划、提取账本、渲染合同、成品证据、发布授权；禁止跳级和乱序。

渲染器只能生成候选及审阅素材，禁止自行生成发布授权或复制到正式目录。独立发布阶段必须绑定候选 PDF SHA-256 与整页／局部 crop 审阅证据 SHA-256，并声明发布动作与渲染进程分离；先复制后审阅再撤销不属于合法流程。

## 1. 目标与质量边界

产出应达到良好并接近优秀，目标质量不低于 90。优先保证：完整翻译、工程含义准确、中文可读、原文关联明确、分区规则正确、图形与表格不受破坏。轻微引线穿过普通线条、局部密度变化和非绝对最短距离是软问题，不因追求像素级完美反复返工。

以下是硬失败：漏翻、错译、译文过短而丢失语义、中文肉眼不可读、方向错误、分区规则错误、目录非逐行双语、公司/项目/地址/联系方式未完整双语、译文未实际落墨、严重遮挡、裁切、乱码、Logo/边框/尺寸/图形损坏。

## 2. 主管与工具边界

- 唯一生产主管：Codex agent `gpt-5.6-sol`，reasoning profile `light`。
- 主管负责看原图、分区、语义分组、翻译、字号、位置、方向、换行、引线和最终视觉复核。
- 原生 PDF 文本和 OCR 只提供候选与坐标；不得决定完整性、分区或位置。
- 参考稿只用于确认译文内容和需翻内容，并与原文核对；不得复制参考像素、坐标、字号或版式。
- 渲染器只执行主管的最终设计。显示坐标写回旋转 PDF 时必须使用正确的反旋转矩阵与文字方向补偿。

## 3. 受控工作流

每页执行三次主管动作：

1. 一次完整视觉分区、内容盘点、翻译和版式规划。
2. 一次定向差集复扫，只检查漏翻、方向、目录逐行双语、侧栏/底栏完整性和字号可读性。
3. 一次成品对照复核，查看整页以及目录、正文、侧栏、底栏的 2× 局部图。

硬缺陷只局部修复；软问题不整页重算。不得用固定 `PASS` 模板或仅凭 JSON 数量批准。

## 4. 内容闭环

- 页面包为每条源文字提供稳定 `line_id`。
- 每个 `line_id` 必须恰好进入一个渲染语义块的 `source_ids`，或在确属纯尺寸、纯编号、代码、邮箱、网址等语言中性内容时进入 `literal_only_ids`。
- 多行可合成完整段落，但 `source_ids` 和 `source_text` 必须保留全部成员内容。
- 整页以及 `drawing_body`、`directory_index`、`company_contact_panel`、`state_bearing_metadata`、`prose_or_index_metadata` 分区闭合率都必须为 1.0。
- 长项目、公司和地址说明必须完整翻译；“项目信息”“公司资料”等短标签不能代替原段落。
- 计划闭环和实际落墨闭环必须同时为 1.0。

## 5. 分区规则

### 5.1 工程正文与工程表格

保留原文、尺寸、符号和图形，在对应说明或对象附近放置完整蓝色中文语义块。翻译方向继承源文字局部方向。先按完整引线说明、标题、设备标签和段落分组，禁止逐词碎片化或跨页合并不相邻标签。

### 5.2 目录与图纸索引

- 每个含可译自然语言的行／单元格必须同时保留原文内容和中文内容，使用黑色文字；纯图号、型号、代码、数值单元格原样保留并记入 `literal_only`，不伪造中文重复值。
- 保留行号、图号、型号、纸张规格、表格线、粗体与层级。
- 遮罩、白块和 redaction 只能覆盖经字形级确认的自然语言 glyph union；与行号列、图号列、尺寸列及表格线的交集必须为 `0`。所有源行号必须逐页可见并与原稿一致，遮罩距结构线和受保护字段至少 `1.5pt`。
- 中文使用单元格实际可用空间内能够容纳的最大字号。本批次字号系数为 `1.20`，优先不低于 `7.2pt`，硬下限 `6.8pt`。
- 文字应贴近对应单元格边界形成清楚层级，但不得压线；边距为 `1.5–3.0pt`，文字利用单元格可用高度约 `72%–90%`。
- 空间不足时先换行、调整原文/中文上下或左右比例、使用同格第二空白区；不得先缩成微小字。
- 目录清除／redaction／白色遮罩只能覆盖经字形级确认的自然语言 glyph union；不得与序号列、图号列、尺寸列或任何表格线相交，并须与结构线和受保护字段边界保持至少 `1.5pt` 净距。发布证据必须包含 `mask-vs-protected-columns` 审计，所有交集计数和交叠面积均为零，并逐页确认原行号可见且与源稿一致。

### 5.3 公司与顾问信息框

- 每个公司框独立测量非 Logo 空白；保护 Logo、Logo 字样、边框、分隔线、印章和签名。
- 公司角色、名称、地址、电话／传真／邮箱／网站字段标签和资质说明全部双语，不只翻标题；电话号码、邮箱地址和 URL 值原样保留，不伪造中文值。
- 保留原文，在同一单元格的 Logo 右侧、下方或第二空白区放置完整黑色中文。
- 本批次字号系数为 `1.18`：先按源层级取得基准字号，乘以系数，再以单元格最大可容纳字号为上限、`6.4pt` 为下限；优先不低于 `6.8pt`。每格独立计算，禁止全侧栏统一小字号。
- 空间不足先换行或使用第二空白区，不得覆盖 Logo，也不得以缩小到不可读字号解决。
- 每个可译块必须且只能选择一种执行模式：①保留原文并在附近放蓝色中文，禁止遮罩；②完整覆盖／清除旧自然语言字形后，以黑色原文+中文双语重排，成品不得再看见旧原文字形。禁止半覆盖、旧文与新双语叠字。公司信息框默认使用模式②；Logo 仅为软保护，应尽量避让，但若轻微遮挡 Logo 是唯一问题，可按动态标准发布。

### 5.4 项目说明、服务标题、图名与状态信息

- 普通项目说明和索引类文字使用层级保持的黑色双语排版。
- 修订、日期、比例、图号、审批、状态和签名等状态信息保留原文及符号，在对应单元格附近加蓝色中文，不做整格擦除。
- 项目清单中的每个枚举项必须分别完整翻译。

## 6. 通用字号与位置规则

- 可读性是发布硬门禁。必须在 100% 审阅比例及 2× 局部图中清楚辨认。
- 译文字号由源文字视觉层级、内容量和可用空白共同决定，采用可容纳的最大字号。
- 正文中文优先不低于 `6.4pt`、硬下限 `5.8pt`，且不低于对应源文字视觉字号的 `85%`。
- 优先顺序：完整语义换行 → 使用邻近或第二空白区 → 短引线 → 轻微压普通辅助线 → 最后才在硬下限以上缩小。
- 译文应靠近对应原文、对象或表格边界；不得漂浮到远处或形成跨页长行。

## 7. 参考稿与翻译

- 参考译文和旧译层必须回链到原文语义，并重新通过 V4 的完整性、分区、字号、位置和实际落墨检查后才可采用；“旧版可信”不能自动保留。
- 参考稿缺失、乱码或错误时，由主管依据原文和本地工程术语知识翻译。
- 禁止 Google 翻译占位、`工程标注：原文`、泛化短标签、私用区字符和英文回显冒充中文。
- 数字、单位、型号、图号、标准编号保持不变；描述性文字必须翻译。

## 8. 发布证据

正式 PDF 必须具备：主管计划、不可变主管运行包、渲染授权、覆盖闭环、实际落墨闭环、逐区截图、最终视觉复核和发布授权。主管自报通过不能替代实际图像检查。用户明确接受某份候选时，可作为该版本的人工发布授权；后续文件仍必须执行最新规范。
